# 0.2.2-preview

## 用户操作

导入视频后，默认点击「自动识别并修复」即可检测并修复当前帧的候选区域。识别结果会先显示边框，处理完成后可拖动分界线比较前后效果。没有识别到区域会明确提示，可换一个时间点重试；手动模式保留为可选功能。

原版画质与轻量流畅由用户选择，轻量模式提供 128×128 和 256×256 两档，选择会改变实际模型输入尺寸。该选择同时用于单帧处理与连续预览。

连续修复支持自动识别、暂停/继续、显示框、实际 FPS、缓冲提示与全屏。原片可全屏有声播放；修复预览当前为静音，尚未导出修复视频文件。

## 停止状态修复

此前点击暂停会等待 native 推理或解码释放，导致界面长期停在「正在停止」。现在点击后立即结束界面播放状态，设置 ORT RunOptions 终止信号，并将未结束的任务隔离到旧工作线程中释放。

每轮播放使用独立代次，停止后的帧回调与 finally 无法修改新播放状态。GPU 释放期间使用新的 CPU 工作线程，避免下一次操作继续排在旧 GPU 任务后。后台释放完成后可重新选择 WebGPU。没有活动的连续播放时，生命周期暂停不会错误清除普通单帧操作的忙碌状态。

## 验证范围

- Android Debug APK 构建和 Kotlin 逻辑测试覆盖 BGR/RGB 通道、批次偏移、视频边界、裁剪、候选去重、停止代次及输入尺寸约束。
- 电脑端 ORT 1.31.1 实际运行轻量模型 128/256，输出形状正确且全部有限。
- 电脑端原版修复模型收到 terminate 信号后退出，之后可用新的 RunOptions 再次正常推理。本次观察终止返回耗时约 4.27 ms；这是电脑端结果，不是手机或 GPU 的延迟。
- 小米 12S CPU 原版模型基线另见测速报告。此次新 UI/连续播放/停止修复按用户选择先交付 APK 与源码，尚未完成新一轮手机验收。
- WebGPU 仍为实验选项，不能把开启开关等同于全图 GPU 或固定帧率。原版处理赶不上播放时会缓冲。

源码不包含手机 APK、从手机提取的私有模型、个人媒体、签名密钥或本地 SDK 配置。模型准备和复现步骤见根 README。
